## real-guard-v1 v0.1.0

An open-source AI Firewall for LLM and agent traffic: it inspects, transforms
and — where policy requires — holds for human approval every request and
response that passes through an OpenAI-compatible API, in front of any
OpenAI-compatible upstream (a real one, or local Ollama with `qwen3:8b`).

This is the first tagged release. Everything below shipped in this one
version; there is no prior release to diff against.

### Highlights

- **A drop-in OpenAI-compatible gateway.** An unmodified `openai` Python
  client works against it unchanged; `docker compose up --build` starts a
  working firewall on `http://localhost:8000` with no `.env` edits, in
  deterministic mock mode (no network, no API key required).
- **Three orthogonal verdicts, two independent axes.** `ALLOW`, `DENY`, and
  `NEED_APPROVAL` are the verdict; `NONE`, `REDACT`, and `MASK` are the
  transformation — declared independently by policy, never conflated.
- **A real, persisted approval workflow**, not a stub: an 8-state machine
  with restart recovery, idempotency keys, replay prevention, exactly-once
  resume, and invalidation when material tool-call arguments change between
  creation and decision.
- **A server-rendered reviewer dashboard** at `/dashboard` — login, a
  status-filtered queue, inline approve/deny — with no JavaScript framework
  and no third-party CDN dependency.
- **Tool-call inspection that never executes anything.** An allowlist,
  high-value-transfer, destructive-SQL, and destructive-shell rule against
  parsed `tools[]`/`tool_calls[]`; the firewall denies or holds, but no
  version of this MVP ever runs a tool itself.
- **A frozen, schema-validated 54-case behavioural corpus**
  (`tests/data/golden_corpus.jsonl`) as an executable contract: 32/32 attack
  cases receive a non-`ALLOW` verdict, 12/12 benign cases pass clean, and
  10/10 PII/secret cases redact correctly — enforced as a CI-blocking gate,
  not just a test suite.
- **A local, real-model integration path.** The `ollama-host` Docker Compose
  profile targets a host Ollama running `qwen3:8b`; the identical corpus
  verdicts hold against real inference, confirming detection does not
  depend on the mock provider.
- **Audit, metrics, and rate limiting.** A structured, append-only audit
  event for every verdict; 25 Prometheus metrics behind `GET /metrics`; a
  persisted per-identity rate limiter; a code-enforced log-field allowlist
  so no raw PII or secret value reaches a log line at any verbosity.
- **Measured, not asserted, performance.** `docs/benchmarks.md` is
  generated by `scripts/benchmark.py` against a real running process —
  firewall-added p50/p95/p99 latency, throughput, and an explicitly-labelled
  derived cost estimate — never an invented number.
- **A documented threat model and residual risks.** Every SPEC.md §19
  threat maps to a control or a stated residual risk in
  `docs/threat-model.md`; `SECURITY.md` states what this release does not
  yet cover (streaming is rejected outright, not partially inspected;
  tool execution is explicitly out of scope).

### Known limitations (stated plainly, not omitted)

- `stream: true` requests are rejected with `UNSUPPORTED_FIELD` — streaming
  support is deferred to a future release with a designed egress-buffering
  approach, not silently unsupported.
- Tool-call inspection never executes a tool; production tool execution
  remains an explicit non-goal of this release.
- Dependency pinning currently uses version ranges (`pyproject.toml`), not
  a hash-locked lockfile; `pip-audit` and Trivy report zero high/critical
  vulnerabilities against the current dependency set, but a compromised
  package registry between releases is a named residual risk (see
  `docs/adr/0011`).
- Firewall-added latency budgets (G1-G3) are aspirational, not
  pass/fail gates; the measured numbers in `docs/benchmarks.md` are mock-mode
  only — real upstream/model latency is not included.
